# Сценарий записи демонстрации

Видео на 60–90 секунд записывается локально на demo dataset. Никакие реальные резюме, email, токены, ключи, IP-адреса или пути пользователя в кадр не попадают.

## Подготовка

1. Откройте терминал в приватном репозитории DevJobs.
2. Поднимите локальный Docker-стек.
3. Примените миграции и создайте demo dataset.
4. Откройте Swagger UI или подготовленный frontend, когда он появится.

Команды:

    docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
    uv run alembic upgrade head
    uv run python -m scripts.seed_demo

Сохраните только напечатанный demo profile ID. Перед записью проверьте, что в терминале не отображаются переменные окружения.

## Таймлайн

| Время | Что показать | Комментарий |
|---|---|---|
| 0–10 сек | Титул DevJobs и задача продукта | «Помогает сравнить профиль кандидата с рынком вакансий» |
| 10–20 сек | Создание demo dataset | Только итог: profile ID и число demo-вакансий |
| 20–35 сек | Swagger: Dashboard endpoint | Показать успешный ответ для demo profile |
| 35–50 сек | Market Fit | Показать score, strengths, gaps и next action |
| 50–65 сек | Vacancies и Roadmap | Показать рекомендации и план развития |
| 65–80 сек | Quality evidence | «Автоматические тесты, CI и Docker smoke в private development repository» |
| 80–90 сек | Финал | «Backend MVP готов; frontend — следующий этап» |

## Обязательная проверка перед публикацией

- В кадре нет .env, токенов, паролей и cookies.
- Нет реальных ФИО, email, резюме и данных HH-аккаунта.
- Нет приватных URL, IP-адресов, локальных путей и идентификаторов.
- Видны только demo-данные и безопасные локальные endpoint-ответы.

После записи добавьте в репозиторий только обезличенный GIF/MP4 или статичные скриншоты в папку docs/evidence/.
